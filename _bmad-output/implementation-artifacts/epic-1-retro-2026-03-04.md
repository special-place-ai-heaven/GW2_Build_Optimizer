## Challenges & Root Causes

### Challenge 1: Package-Name Mismatch (P1-02)

**What happened:** Story ACs and verification commands used `gw2_addon` (directory name). Actual Cargo.toml package name is `gw2-build-optimizer`. Dev had to discover and correct during implementation: fixed story ACs, CI yaml, and verification commands.

**Root cause:** Story author read the *crate directory name* (`crates/addon/`) and used it in commands without checking `[package] name` in `Cargo.toml`. In Rust workspaces, directory names and package names are completely independent.

**Impact:** Low (caught in implementation), but story shipped with wrong artifacts baked in. CI yaml would have been incorrect if deployed verbatim.

**Prevention:** SM-1 checklist item — see Process Updates section.

---

### Challenge 2: Spawn-Count Estimate Drift (P1-03)

**What happened:** Story AC6 stated `wc -l == 13` for thread spawn count. Actual count was 10. Dev correctly noted the discrepancy and completed the story, but the AC would have failed its own verification command if run literally.

**Root cause:** Story author performed a rough visual scan of a 3,621-line file. The estimated count was not verified by running the command against live code before writing it into the story.

**Impact:** Low (story succeeded, dev handled it correctly), but a strict AC interpretation would have blocked completion.

**Prevention:** SM-2 checklist item — see Process Updates section.

---

### Challenge 3: Sprint-Status Lag (P2-04 + epic-1)

**What happened (two instances):**
1. P2-04 story file header remained `Status: review` after all work was done and committed. Sprint-status.yaml correctly showed `done` but the story file was never updated.
2. epic-1 remained `in-progress` in sprint-status.yaml after all 5 stories completed. No process step triggered the epic promotion.

**Root cause:** Two sources of truth (story file header + sprint-status.yaml) with no enforced sync rule. The sprint-status update was included in DoD, but story file header update was not. Epic auto-promotion was similarly not captured.

**Impact:** Required manual cleanup at sprint closeout (found during sprint-status reconciliation). If missed, retrospective would have been blocked by misleading status.

**Prevention:** DoD-1 and DoD-2 additions — see Process Updates section.

### Background Thread `catch_unwind` Hardening

**Status:** Deferred from P1-02 and P1-03 — carried forward as Epic 2 backlog item P2-03
**Priority:** Medium
**Owner:** Dev (Amelia)

**What it is:** 10 background threads in `main_view/` (distributed across `optimization.rs` ×2, `stats.rs` ×4, `character.rs` ×2, `mod.rs` ×2) lack `catch_unwind`. The optimizer thread is correctly wrapped; all others are not.

**Risk:** If any unguarded thread panics, its `loading = true` flag is never cleared → permanent loading spinner → user must restart GW2.

**Scope:** Wrap each spawn body in `catch_unwind(|| { ... })`. In the `Err(panic)` arm: log a warning via Nexus log, then clear the relevant loading flag via `with_state`. Add at minimum one test per loading-flag-under-panic path.

**Must complete before:** any user-facing feature story in Epic 2.
