Rules:

- One row per trait in `cache/traits.json`, grouped by profession then line then `tier, order`.
- `State` is derived, never typed: `facts` if the parser or builder consumed a fact; `record` if an executable record exists for WvW; `facts+record` if both; else the record's `coverage.class` (with `mechanic`); else `NoRecord`.
- The test fails when any profession that has shipped its increment (listed in the test) has a `NoRecord` count above zero, and when any trait has no row.
- The summary's `NoRecord` column is the sprint's progress bar: it reaches 0 per profession as increments land.

## Wiki-number check

`records_match_their_wiki_pages`, `#[ignore]`, reads `wiki_api` from `dev.cfg` (the MediaWiki `api.php` URL; skips with a printed reason when absent) and, for every record whose `source` starts with `https://wiki.guildwars2.com/`:

1. Fetches the page's wikitext through the wiki API (`action=parse&prop=wikitext`, one request per distinct URL, cached for the run). The rendered page shows the PvE column and hides the competitive facts behind mode tabs; only the wikitext carries every `game mode=wvw` fact, so a crawl of the rendered page cannot do this check (found 2026-09-08: 50 of 149 records "mismatched" against the rendered markdown, every one a competitive split).
2. Reads the numbers of every fact template; a single stack or count (`1`) is implicit on the page and not checked. A record with `derived_from` is checked through those page numbers instead of its `value`. The cached API facts of the trait or skill count beside the page (percent, number, recharge, time, attribute, buff duration and apply count): the game's own data is a source the page may leave to the tooltip. Records whose `evidence_level` is not `Factual` are skipped by name: their numbers are estimates, not page claims.
3. Asserts every factual number in the record (`value`, `effect_duration`, `internal_cooldown`, `max_stacks`, `status_operation.amount_value`, `base_duration_ms / 1000`, `target_count`, `prerequisite.foe_health.percent`, `healing_power_coefficient`) appears in that text as a number token.
4. Prints one line per record: `ok trait:2020:0 Chilling Nova` or `MISMATCH trait:2020:0 Chilling Nova: 1.125 not on page`.

A release of a profession increment requires a clean run of this check on that profession's records (FR-010a); the run's output is pasted into the audit section for the increment.

No page content is committed; the check reads, compares and prints.
